# n8n workflows

13 workflows. `workflows/*.json` is generated by `build_workflows.py`; edit the
builder and regenerate rather than editing JSON by hand.

```bash
python3 build_workflows.py                      # regenerate
python3 ../scripts/gen_workflow_docs.py         # regenerate docs/02-workflows.md
python3 ../scripts/validate_workflow_sql.py | psql -d zenvexa_acq   # type-check the SQL
node ../scripts/test_code_nodes.mjs             # run the Code nodes against fixtures
```

`test_code_nodes.mjs` extracts the real `jsCode` out of the committed JSON — not
a copy — and runs it under a small shim of the n8n runtime. A failure there means
the deployed node is wrong. It covers the logic most likely to break: the OSM
normalizer, the robots.txt reader, email extraction, both guardrail passes,
bounce vs auto-reply detection, reply classification routing, and the AI response
validator.

The builder validates as it writes: duplicate node names, connections to
non-existent nodes, and unreachable non-trigger nodes all fail the build.

## Importing

```bash
docker compose exec n8n n8n import:workflow --separate --input=/workflows
```

Or drag each file into the n8n UI.

## After importing — five things, once

1. **Credentials.** Create them with these exact names, then open each
   red-flagged node and select the real credential:

   | Name | Type | Notes |
   |---|---|---|
   | `acq-postgres` | Postgres | the `zenvexa_acq` database |
   | `zenvexa-smtp` | SMTP | your outreach mailbox |
   | `zenvexa-imap` | IMAP | the same mailbox |
   | `acq-telegram` | Telegram API | bot token from @BotFather |
   | `gemini-api-key` | Header Auth | name `x-goog-api-key`, value your key |
   | `google-places-key` | Query Auth | name `key`, value your key |

2. **Sub-workflow links.** Every *Execute Workflow* node has a
   `REPLACE_WITH_ID__…` placeholder. Point each at the workflow named in the
   node's own note.

3. **Error workflow.** On every workflow except 00: Settings → Error workflow →
   *ACQ 00 — Error Handler*.

4. **Webhook URLs.** Copy the production URLs for workflows 110 and 100 and
   store them:
   ```sql
   UPDATE acq.settings
      SET value = to_jsonb('https://n8n.you.tld/webhook/unsubscribe'::text)
    WHERE key = 'unsubscribe.base_url';
   ```

5. **Timezone.** The compose file sets `GENERIC_TIMEZONE=Asia/Karachi`, so cron
   expressions mean local time. Change it and every schedule shifts.

## Activation order

Do not switch all 13 on at once — see [docs/09-build-order.md](../docs/09-build-order.md).

| Phase | Activate |
|---|---|
| 1 | 00, 10, 20 — discovery only, no AI, no mail |
| 2 | 01, 30, 40 — research and drafting, `dry_run = true` |
| 3 | 110, 50, 60 — first real sends, human-approved |
| 4 | 70, 80, 90, 100 — replies, follow-ups, demos |

## Conventions

- **Placeholders, not secrets.** Credential ids in the JSON are deliberately
  invalid so an import cannot silently pick up the wrong credential.
- **SQL parameters, never interpolation.** Every query uses `$1` placeholders
  fed by `options.queryReplacement`. Nothing a discovery source or a prospect
  writes can reach the query text.
- **One jsonb parameter where it fits.** `upsert_lead($1::jsonb)` and friends
  take a single JSON argument, which removes a whole class of
  argument-ordering bugs.
- **Retries on I/O, not on logic.** HTTP and Postgres nodes retry 3× with
  backoff; Code nodes do not.
- **`alwaysOutputData` on claim queries**, so an empty batch flows through to
  the run-recording node instead of stalling.
